# v0.4.0 作業記録

状態: 2026-10-11。V0.4.0の確定範囲を実装し、クラウドで検証済み。Devと本番向けの同版配布は利用者の承認済み。Mac本番の適用はクラウドから実行しておらず、実行後のWeb・収集・URLの確認はMac側で行う。

## 実装した範囲

- ダッシュボードの自枠での対象選択は維持し、自枠の基準記録 `own_observation` と全DJでの最新観測 `latest_observation` を分離。コンパクトな3列では全枠の最新出現先・温度・日時を表示する。一覧の取得は対象IDをまとめた照会で、通常更新へ人ごとのHTTP要求を追加しない。
- 展開時に自枠の基準より厳密に後の履歴を取得する。新しい順、30件ごとのIDカーソルで追加表示。同時刻・未来の記録を後続へ混ぜず、温度0／欠損、部分取得を維持。名前からDJの詳細を開ける。観測順は移動・退室・連続滞在の証明ではない。
- 自分のプロフィール設定後、登録ファンがいなくても、今月の自枠での実観測者・自枠の月間温度が正のメンバーを閲覧できる。2つの候補と申告に基づく登録ファンを区別し、全件の絞り込み・並び替え・活動分類後にページ分割する。
- スマホ向けの検索・複数選択・名前／数値IDの確認・ファンの部分追加を実装。既存のimportを `complete:false` で使い、既存の登録を置き換えない。新しい個別解除APIはログインアカウント内の対象者だけを解除し、ほかのファン・配信者設定・お気に入り・共有の観測・別アカウントを保持する。
- 画像補助を独立したES moduleへ実装。ブラウザ内のTesseract.js Workerと同じサイトから提供する日本語／英語の読取データを使用し、画像は端末内で処理する。画像は一度に3枚、各8MB、合計16MBまで。縮小・30候補・検索並列2件・中止／時間切れ・候補編集・数値ID選択・共通の登録確認を実装。パスワード・Cookie・トークンを要求せず、全件フォロワーの自動取得とは扱わない。
- 管理一覧をnative `details` に変更し、常時表示はログイン名と実際の権限だけ。展開内に既存のタグ・紐付け・パスワード・権限・削除操作を保持する。保存後も展開状態を保持し、表示タグとアクセス権限を分離する。
- スマホの詳細出現先の名前欄が1文字幅になる問題を修正。名前とIDを上段へ、観測情報を下段へ置く。モーダルの見出しはスクロール領域の外、本文だけをスクロール。狭いPC詳細ペインと長い名前／IDにも対応する。
- 聴取中の目安の判定窓を、正常なworkerと同起動中に完了した巡回時間・待機時間に基づいて600〜1800秒に調整。停止・失敗・部分取得・通信制限待機・古いheartbeat・巡回停滞・情報不足では600秒を保持する。新しい対象枠の失敗や温度なし／不在は、過去の温度から現在の聴取を作らない。最近の観測は1800秒のまま。
- 既存の30秒確認・60秒要求上限・背景通信の中断防止・手動変更時のsequence／AbortController照合・100人ごとのお気に入り取得を保持する。観測日時と表示確認日時を分け、V0.4.0の履歴と版番号を表示する。

## 残る事項と運用上の限界

「まめ／ゆん」の元の0表示について、本人の数値ID・ファン登録API診断は未取得。一般的な判定窓・表示の改善を実装したことだけで、そのMac事例の実原因を確定したとは扱わない。

画像補助の読み取り精度は端末・画像・装飾文字に依存する。クラウドのブラウザ検証と利用者のiPhone／Android実機での精度を区別する。公式OAuth／フォロワーAPI連携・ブックマークレットは未対応。個人メモ／タグ、対象期間の追加切替、配信後の振り返りは未採用・未実装の追加提案。

本番リリースは [Dev確認・Mac更新](v0.4.0-dev.md) のコマンドで、バックアップ後にコードだけを更新する。既存ユーザーとパスワード、配信者設定、ファン、お気に入り、収集記録を保持し、正常な既存の収集サービスの再導入は不要。検証済みの公開ランチャーとTunnelが動いている場合はWebだけを再読み込みし、URLを保持できる。停止したQuick Tunnelを新規起動した場合の同一URLは保証しない。

このクラウドから利用者のMacへ接続していない。GitHubへ同じコードを配布することと、Macで本番コードが稼働することは別であり、Mac本番の実行・起動成功・公開URL保持は利用者の確認待ち。
