# v0.2.1 Dev確認

Devブランチ: `dev/v0.2.1`。Mac本番への公開操作は含めていません。

## 変更点

- 配信者の初回確認と確定後の変更制限。一般ユーザーによる直接APIからの変更・解除も拒否します。
- 管理者からの対象ユーザーの配信者修正、操作履歴、既存紐付けの移行。
- 「利用者・管理者・テスト」の選択式タグ、追加候補、既存タグの保持。タグと権限は別操作です。
- 左ナビをダッシュボードとリスナー検索に整理。検索内にお気に入り・ファン検索を置きました。
- 右上にアカウント、管理コンソール、説明・変更履歴・文書の入口を配置しました。
- 共通のリスナー指標とDJ別Spoonをダッシュボード・詳細・お気に入り・ファン一覧に表示します。
- `collect-auto` による永続キュー、対象DJの自動登録、並列収集、共有待機、重複起動防止。
- 枠ごとの実際の取得境界・ページ数・失敗を記録。429でも取得済みの正の観測を保持します。

パスワード・お気に入り・ファン設定は引き継ぎます。この更新を理由に既存ユーザーのパスワード変更を求めません。
未確定の利用規約・プライバシー文書は「準備中」です。Spoon紐付けは本人認証ではありません。

検証: Pythonの全196テストが成功。認証付きHTTPサーバーで320・390・1365pxのブラウザ確認74項目が成功し、JavaScriptエラー・ページ横スクロールはありません。きー（316644201）としらたまもなか（312029086）の実APIの先頭ページでも、数値のSpoonを確認しました。Mac本番の稼働・全件取得を確認したものではありません。

## 指標の現在の状態

| 項目 | 表示と条件 |
| --- | --- |
| 滞在指数 | 過去28日間の複数DJでの継続観測・再観測を使う参考値。有効比較10組、観測3日、2DJ以上などの条件を満たした場合に算出。実際の滞在分数ではありません。 |
| 自枠のSpoon | 自DJの取得済み公開ランキング値。未取得・額不明・ランキング不在は0にしません。 |
| DJ別Spoon | 発見済み出現先の取得値、日時、部分取得、直前の取得済み記録と最新失敗を表示します。 |
| 応援先の広がり | 十分な取得範囲・鮮度の条件を満たす場合に、確認できた応援先の数から参考値を算出。金額で重み付けしません。 |
| 投げ指数の合成点・金額の集中度 | 集計期間がAPIで確認できないため算出しません。期間確認と比較条件の検証が必要です。支援確率を表示しません。 |

滞在の欠測、部分取得、長い間隔、枠変更、遅いページ取得、同一取得回の重複を考慮します。
観測が不足する場合は「材料不足」であり、公開直後から全員に数値が出る仕様ではありません。

## MacのDevで確認する

DevのWebが動いている場合は、そのターミナルでCtrl+Cにより止めてから更新します。

```bash
conda activate spoondev
cd ~/SpoonDev-dev
git fetch https://github.com/APLAquilone/SpoonDev.git dev/v0.2.1
git switch -c dev/v0.2.1 FETCH_HEAD
python -m pip install -e .
bash scripts/start-dev-mac.sh
```

既に同名ブランチがある場合は `git switch dev/v0.2.1` と `git merge --ff-only FETCH_HEAD` を使います。
画面は `http://localhost:8081`。Dev用ログインアカウントを使います。
未コミットのローカル変更がある場合、Gitの変更保護を維持して先に保存してください。

Devは保存済み観測で起動します。独立したDev観測の収集を明示して有効にする場合:

```bash
SPOONDEV_COLLECT=1 bash scripts/start-dev-mac.sh
```

旧手動収集を同じDBで起動している場合は、各ターミナルで停止してから自動収集に切り替えます。
既定のライブ更新は300秒、月間・Spoonは3600秒を基準にスケジュールします。
実際の更新には処理時間、共有リクエスト待機、上流の反映遅れが加わります。
すべてのSpoonアカウントや実際の訪問先を網羅するものではありません。

## 公開する際の扱い

Devレビュー後、従来の `release-mac.sh` を使います。DevのDBを本番へコピーしません。
新しい公開ランチャーは自動収集を起動し、Webの再読み込みでは収集とTunnelを保持します。
既存v0.2.0ランチャーで公開中の場合、Webだけの更新では収集workerは追加されません。
URLを維持して収集を移行する初回手順はREADMEの「自動収集と起動」を参照してください。
