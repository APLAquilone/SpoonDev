# v0.4.0 検討事項

状態: 構想・計画のみ。実装と本番への適用は別途行う。

## 自枠に来たリスナーの、その後の出現先

- [ ] ダッシュボードで、自枠に来た人がその後どの枠で観測されたかを確認できるようにする。

2026-10-11の追加要望。提供画像 `6952.jpg` の「最近観測したリスナー」では、「最近のリスナー観測」がきーの枠と自枠での観測時刻を表示している。しかし、その後に別の枠で観測されている場合もある。自枠への訪問を起点に、他枠も含めた後続の記録を見たい。

### 現在の表示と問題

現在のダッシュボードは、自分に紐付けた配信者の最新取得一覧から最大20人を選び、一覧の出現先もその配信者に固定している。自枠での最終観測が、Spoon全体でその人を最後に観測した場所・時刻のように見えてしまう。

実装時の調査対象は `spoondev/dashboard.py` の `_listeners()`・`summary()` と、`spoondev/static/index.html` の `compactListenerTable()` のdashboard分岐。全DJを対象にした既存のリスナー観測・出現先取得を再利用する方針とする。

### 表示方針

- 対象者は、自分の枠で観測されたリスナーから選ぶ。
- 一覧の「最近のリスナー観測」は、対象者ごとに他枠も含めた最新の保存済み観測を表示する。自枠が実際に最新なら自枠を表示する。
- 自枠での観測が30分以上前でも、他枠では最近観測されている場合がある。自枠での古さを、その人の全枠での古さとして使わず、全枠の最新日時・最近の活動判定を取得し直す。
- 「自枠で最後に観測した日時」と「他枠も含む最新の観測場所・日時」を分けて保持する。カードの自枠の取得時刻と、行ごとの最新観測時刻も区別する。
- 名前・最新の出現先と日時・お気に入り登録のコンパクトな3列を維持する。出現先の名前から配信者の詳細を開けるようにする。
- 行を展開すると、自枠での観測と、それ以降の観測先・日時・その観測で取得できた温度を時系列で確認できるようにする。
- 月間温度、プロフィール確認日時、自枠での観測温度を、他枠の最新リスナー観測として流用しない。

### 観測の扱い

- 数値IDで同一人物を識別し、表示名の重複・変更で別人の履歴を混ぜない。
- 自枠での基準となる観測より後の記録だけを「その後」として扱う。日付をまたぐ記録も日本時間で表示し、未来の記録は除外する。
- 「自枠で観測 → 他枠で観測」という記録の順序を示す。巡回には時間差があるため、実際の移動時刻・退室・連続滞在を断定しない。同時刻や近い時刻の別枠観測では、確定した移動順として扱わない。
- 後続の記録がなければ「その後の観測なし」と表示する。自枠に居続けている、Spoonを閉じた、他枠へ行っていないとは判断しない。
- 温度なし・部分取得・収集の空白を区別する。「いま聴いている」の目安と履歴を混同せず、古い観測から現在地を作らない。

### 性能・アカウント分離

- 一覧の対象IDをまとめて照会する。対象者ごとの全履歴取得や個別HTTP要求を通常の一覧更新に追加しない。
- 詳細な時系列は展開時に必要な範囲だけ取得し、期間指定・件数制限・ページ分割を検討する。
- 対象リスナーの選択元は、ログインアカウントに紐付いた自枠の観測とする。別アカウントの配信者設定・ファン・お気に入りは混ぜない。一般利用者の配信者紐付けロックも維持する。

### 完了条件

- 自枠で観測後に他枠で観測された人は、一覧で他枠の名前と新しい日時が表示される。
- 自枠が最新の場合は自枠を表示し、その後の観測がない場合は未知として表示する。
- 展開すると自枠の観測と後続の観測を区別でき、再訪・複数の出現先・日付変更も確認できる。
- 温度0・温度欠損・部分取得・同名別人・未来の記録・収集停止・長い表示名でも意味やレイアウトが崩れない。
- 最新の自枠の配信が古くても、対象者の新しい他枠観測が古い自枠の時刻で上書きされない。
- スマホの一覧性とアカウント間の分離を保持し、一覧更新の処理量を実測する。

未確定: 対象リスナーを選ぶ期間（直近配信／直近7日など）、時系列を表示する期間、既定の並び順。まず既存の自枠リスナー一覧を改善することを優先する。

## ユーザー管理一覧の折りたたみ

- [ ] 管理コンソールのユーザー一覧を、名前と権限だけで見渡せる形にする。

2026-10-11の追加要望。提供画像 `6954.jpg` では、各ユーザーのタグ・パスワード状態・配信者設定・操作ボタンがすべて表示され、1人分の高さが大きい。常時表示は名前と「管理者／利用者」だけにしたい。

### 表示方針

- 初期状態は全員を折りたたみ、1行に名前（ログインID）と権限バッジを表示する。展開できることは小さな矢印で示す。
- 権限バッジは実際の `role` を使う。「管理」「保守」「テスト」などの表示タグから権限を判断しない。
- 名前または行を押すと、そのユーザーの設定・操作を下に展開する。
- パスワード設定状態、表示タグの選択・保存、登録DJ、配信者の紐付け修正、初期パスワード再設定、権限変更、削除は展開内にまとめる。
- 設定を保存した後も誰を操作しているかが分かるようにし、権限変更時は一覧のバッジを更新する。
- スマホでも名前と権限を同じ行で読める幅を確保する。長いログインIDで横にはみ出さず、展開操作はキーボードでも使えるようにする。

### 維持する制約

- 管理画面・管理APIの管理者権限確認、CSRF、確認ダイアログは維持する。折りたたみをアクセス制御の代わりにしない。
- kitomoyaの管理者権限解除禁止、自分自身の管理者権限変更禁止、管理者削除禁止など、現在の操作制約を維持する。
- 表示タグの変更でアクセス権限を変えない。パスワード再設定と本人のパスワード変更の導線も混同しない。

### 完了条件

- 通常の一覧では名前・管理者／利用者以外の設定情報や操作ボタンが並ばず、複数人を見渡せる。
- 1人を展開すると、そのユーザーの必要な情報と許可された操作が表示される。
- 展開内の保存・権限変更・パスワード再設定・削除は、対象を混同せず既存の制約どおり動作する。
- スマホ・PC・キーボード操作で展開と折りたたみができ、設定操作で意図せず閉じない。

実装時の調査対象: `spoondev/static/index.html` の `loadAdmin()`、`.admin-user`・`.admin-main` とテーマの文字サイズ・幅。

## PCを持たない利用者のファン登録

- [ ] PCの開発者ツールとJSON保存を必須にしない、スマホ向けの利用開始・ファン登録を検討する。

2026-10-11の追加相談。利用者がPCを持っていない場合、SpoonのConsoleで一覧を取得してJSONを登録する現在の導線は難しい。運営による代理のPC作業を前提にせず、スマホだけで使い始められることを目標にする。以下は検討案であり、実装や採用決定ではない。

### 現在の制約

現在の取得スクリプトは、本人がSpoonへログインしたブラウザ上で本人IDを照合し、フォロワーの数値ID・名前だけを取り出す。認証なしの一覧取得は既知の照合で403となっている。InsightsにプロフィールIDを登録しただけでは、本人限定のフォロワー一覧を取得できない。フォロワー読取権限を持つ公式API・OAuth連携が提供されるかは未確認。

### 推奨する利用開始の候補

1. スマホで自分のSpoonプロフィールを登録する。
2. 保存済みの「今月自枠で観測した人」「自枠の月間温度メンバー」からダッシュボードと出現先確認を使えるようにする。未取得の場合は取得待ちとして表示する。
3. ファン一覧は必要な時に追加する。スマホの検索結果から複数人を選び、登録前に対象者を確認する。フォロワーであることは本人の申告として扱う。

訪問者・月間温度メンバーを自動で「フォロワー」とは扱わない。対象者の選択作業は残るため、検索・選択だけで大人数の全件登録が済むとは説明しない。

### 一括登録の候補

| 候補 | スマホでの体験 | 検討・検証する条件 |
| --- | --- | --- |
| スマホ向けブックマークレット | 本人がSpoonへログインしたブラウザのプロフィール上で取得処理を実行する | Consoleは省けるが、初期のブックマーク設定・ブラウザ制限・Spoonの画面変更への対応が必要。iPhone Safari・Android Chromeとファイル受け渡しを実機で検証する。唯一の利用開始手段にはしない。 |
| フォロワー画面の画像から候補を作る | スマホの画像を読み取り、公開検索で候補を照合して本人が選ぶ | 表示名だけで自動確定せず、数値IDへ照合する。同名・装飾文字・読み取り誤り・取りこぼしを考慮し、部分一覧として追加する。全件置換には使わない。 |
| 公式のフォロワー連携 | 公式の認可画面で許可し、一覧を取り込む | 必要な読取権限の提供を確認できた場合の候補。現在対応できるとは約束しない。 |

まずスマホでの検索・複数選択と、ファン未登録でも使える入口を優先候補とする。一括登録の補助は、その後に実機の成功率と保守負担を比較して決める。既存のPC向け取り込みは補助手段として残せる。

### 完了条件

- PCとJSON操作なしで、自分のプロフィール登録から保存済みのリスナーデータを確認できる。
- スマホからファンの検索・複数選択・確認・追加ができ、同名でも数値IDで区別する。
- フォロワー・訪問者・月間温度メンバー・手動の申告を区別し、未取得を空の全件一覧として扱わない。
- 部分登録で既存のファンを削除せず、紐付けロックとアカウントごとの保存領域を維持する。
- 本人のSpoonパスワード・Cookie・トークンをInsightsへ提出する手順を追加しない。

実装時の調査対象: `spoondev/fans.py`、`spoondev/static/fan-export.js`、ファン検索の初回設定・取り込みUI、既存の対象リスナー集計。
