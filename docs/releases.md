# Macでの開発・公開更新とバックアップ

開発は `~/SpoonDev-dev` の `http://localhost:8081`、公開は `~/SpoonDev` の8080で動かします。コード・ログインDB・お気に入り・ファン設定は別々です。公開用のデータをDevへ上書きする処理はありません。

## 確認した変更を公開する

開発で変更を確認し、Gitにコミットしてから実行します。公開用の `start-public-mac.sh` が動いていれば、**公開ターミナルをCtrl+Cで止める必要はありません**。

```bash
conda activate spoondev
cd ~/SpoonDev-dev
bash scripts/release-mac.sh
```

この処理はDevのテストを実行し、両フォルダに未保存のコード変更がないこと、公開側からDevへfast-forwardできることを確認します。その後、公開側のDBをバックアップしてからコードを反映します。検証済みの公開ランチャーが動いていれば、既存の `reload-public-mac.sh` でWebだけを再起動します。Tunnelは動いたままなのでURLは維持されます。公開ターミナルで `Web reloaded` とWebの起動ログを確認してください。切り替え時には短い接続中断があります。

公開用が停止している場合はコード反映まで行い、起動コマンドを表示します。Quick Tunnelを新しく起動するとURLが変わります。Macの再起動やTunnel停止後もURLを固定するには、独自ドメインとNamed Tunnelが必要です。

8080に不明なサーバーが動いている場合、分岐したコミット・未保存変更・Gitに含まれた `data/` がある場合は停止します。強制上書きや自動マージは行いません。収集処理は止める必要がありません。

## バックアップに含まれるもの

保存先は公開用の `data/backups/日時-コミット-識別子/` です。次を保存します。

- 更新前後のコミットID・ブランチ・日時を記録した `manifest.json`。Gitにも `refs/sci/releases/…/before` と `after` を残し、以前のコードを参照できます。
- `data/` 内のSQLite DB。通常は観測・月間温度・Spoonランキングの `spoondev.sqlite3`、ログインの `accounts.sqlite3`、全ユーザーの `account-data/…/private.sqlite3` です。
- DBごとのバックアップ開始・完了日時とコピーしたファイルサイズ。

SQLiteのbackup機能でWALを含む一貫したコピーを作り、`quick_check` を実施します。DBごとには一貫していますが、複数DBすべてが同じ瞬間の状態になるわけではありません。アカウント作成中に追加されたプライベートDBも再走査します。ログ・一時的なランチャー状態・Cloudflareの認証ファイルは含めません。`data/` 外の独自DBパスはこの処理の対象外です。

バックアップのディレクトリは700、ファイルは600です。パスワードのハッシュや有効なセッションを含むため、バックアップ自体も公開・共有しないでください。Devへコピーする対象ではありません。

大きいDBではコピーと検証に時間・ディスク容量が必要です。収集が激しい場合、SQLiteのbackupが再試行することもあります。1つのDBにつき既定で10分まで待ち、失敗した場合はコード反映前に停止します。必要な場合だけ待ち時間を増やせます。

```bash
bash scripts/release-mac.sh --backup-timeout 1800
```

バックアップは自動削除しません。容量を確認し、別ディスクに安全に保存したものから手動で整理してください。失敗したバックアップは `manifest.json` の `state` が `backup_failed` で、復元用の完了データとして扱えません。

コードを更新せずバックアップだけ作る場合は、公開用から実行できます。

```bash
cd ~/SpoonDev
bash scripts/backup-public-mac.sh
```

## 問題があったらコードだけ戻す

実際の更新前バックアップのパスを指定し、公開用から明示的に実行します。公開用ランチャーは起動したままで構いません。

```bash
cd ~/SpoonDev
bash scripts/rollback-public-mac.sh data/backups/表示されたバックアップ名
```

指定した更新のコミットが現在の公開コミットと一致することと、未保存のコード変更がないことを確認します。現在のDB・コード参照をもう一度バックアップした後、`git reset --keep` でその更新前のコードに戻し、起動中であればWebだけを再読み込みします。履歴はバックアップ用のGit参照にも残ります。

**DB・お気に入り・ファン設定・変更したパスワードは復元も削除もしません。** 戻す間にも収集した記録を保持します。v0.2.0の追加テーブル・カラムは古いコードで使わなくても残します。破壊的なDB変更を含む将来の更新では、コードだけ戻せるかを別途確認する必要があります。

データの復元が必要な事故では、Webと関連する収集処理を止め、現在のDBを退避してから、対象ユーザー・DB・取得時刻を確認して個別に復元してください。このスクリプトはデータの自動復元を実行しません。

公開切り替え後の動作不良で自動ロールバックは行いません。更新後はログイン、ダッシュボード、お気に入り、ファン一覧を確認してください。Macの実運用でのTunnel・再読み込みは、公開ターミナルのログでも確認してください。
