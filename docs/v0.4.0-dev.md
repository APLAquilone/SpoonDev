# v0.4.0 のDev確認とMac本番への反映

v0.4.0は、自枠に来た人の全枠での最新観測、スマホだけのファン登録、コンパクトな管理一覧を追加する更新です。クラウドで実装・検証し、同じコードを `dev/v0.4.0` と `main` へ配布します。利用者のMacへの接続はなく、この文書の作成だけでMac本番のコード・プロセス・公開URLは更新されません。

## Devと本番をまとめて更新する

今回のDevと本番への反映は利用者の承認済みです。Macの公開用ターミナルと、正常な既存の収集サービスは動かしたままで、別ターミナルから実行します。

```bash
conda activate spoondev &&
cd ~/SpoonDev-dev &&
bash scripts/update-dev-mac.sh dev/v0.4.0 &&
bash scripts/release-mac.sh
```

`&&` により、取得・インストール・テスト・バックアップのどこかで失敗した場合は、その後の処理へ進みません。DevのWebが動いている場合は、Dev用ターミナルだけをCtrl+Cで止めてから更新し、あとで `bash scripts/start-dev-mac.sh` で起動します。公開用ターミナルは止める必要がありません。

リリースはDevのテストとGitの整合性を確認し、本番の観測DB・ログインDB・各アカウントの私有DBをバックアップしてから、コードをfast-forwardします。Devのデータを本番へコピーしません。既存のパスワード・配信者設定・お気に入り・ファン一覧・観測記録は保持し、この版への更新だけで全ユーザーへパスワード変更を要求しません。

検証済みの公開ランチャーとTunnelが動いている場合は、Webだけを再読み込みしてURLを保持します。`Requested web reload` は要求したことを示すログなので、公開用ターミナルでWebの起動成功と実際のページ表示を確認してください。Tunnelが停止していた場合、新しいQuick Tunnelの起動ではURLが変わります。既存URLを保持できる条件とバックアップ・ロールバックは [Macのリリース手順](releases.md) を参照してください。

正常に動いている収集サービスの再導入・古いPIDを使った停止は不要です。今回の更新は保存済みの観測の取得・表示を改善し、収集の二重起動や追加の全件巡回を必要としません。

## Devだけで確認する

```bash
conda activate spoondev &&
cd ~/SpoonDev-dev &&
bash scripts/update-dev-mac.sh dev/v0.4.0 &&
bash scripts/start-dev-mac.sh
```

画面は `http://localhost:8081` です。Devは既定で保存済みの観測を表示し、自動収集は停止しています。本番とはログイン・ファン・お気に入り・プロフィール設定が別々なので、Dev側のアカウントでログインします。Devでの登録・解除は本番へ反映されません。

`~/SpoonDev-dev` がまだない場合は、公開用フォルダで `bash scripts/prepare-dev-mac.sh` により作成し、Dev用のログインアカウントを作成してから上記を実行します。この準備では観測のコピーを作りますが、本番のログイン・私有のファン／お気に入り設定は引き継ぎません。

## 自枠に来た人の、その後

ダッシュボードの対象者は、これまでと同じく自枠の最新取得一覧から最大20人を選びます。コンパクトな一覧の出現先・日時・温度は、その人を**他枠も含めて最後に観測した記録**です。自枠での最終観測と全枠の最新観測を別々に保持し、古い自枠の時刻で新しい他枠の記録を上書きしません。

行の⌄を押すと、自枠で最後に観測した基準記録と、その時刻より後の観測を新しい順に表示します。履歴は展開時に取得し、30件ずつ追加表示できます。出現先の名前から配信者の詳細を開けます。後続がない場合は「その後の観測なし」で、ほかの枠へ行かなかった・Spoonを閉じたとは判断しません。

観測の順序を示すもので、実際の移動・退室時刻や連続滞在時間ではありません。同時刻の別枠観測は「その後」に含めず、未来の記録は除外します。温度0、温度なし、部分取得を区別します。

## PCなしで利用開始・ファン登録

1. ファン検索で、自分のプロフィールを名前・プロフィールID・数値IDから検索し、確認画面で確定します。一般利用者は確定後に変更・解除できず、修正は管理者へ依頼します。この登録はSpoon側の本人認証ではありません。
2. ファン未登録でも「今月自枠で観測」「月間温度メンバー」を選んで保存済みデータを確認できます。今月の自枠の実観測者と、自枠の月間ランキングで温度が正の人を対象にします。取得待ち・空の取得済み一覧・部分取得は区別します。
3. 「検索してファンを追加」から複数人を選び、登録前に名前と数値IDを確認します。ご自身がSpoonのフォロワー一覧で確認した対象として追加します。部分追加なので、既存のファン一覧は置き換えません。
4. 登録ファンの「解除」では、その1人だけを確認して解除します。ほかのファン・配信者設定・お気に入り・共有の観測記録・別アカウントの登録は保持します。従来の「ファン一覧の設定を解除」とは別操作です。

訪問者・月間温度メンバーを自動でフォロワーとは扱いません。Spoonでのフォロー・解除は自動同期せず、登録は本人による対象確認に基づきます。PCで保存したJSON・数値IDの取り込みも補助手段として残します。

### フォロワー画面の画像から候補を作る

ファン検索の「フォロワー画面の画像から追加（補助）」で、JPEG・PNG・WebPの画像を選びます。日本語・英語のOCRはブラウザのWorkerで実行し、画像そのものをサーバや外部OCRサービスへ送りません。約7.6MBの読取用データをこのサイトから取得します。選んだ検索名は公開ユーザー検索へ、確認した数値IDはファン登録APIへ送ります。

1回に画像3枚、1枚8MB、合計16MBまで。画像は端末内で縮小し、候補は編集可能な最大30件に絞ります。「候補を検索」後に同名・装飾文字・読み取り誤りを確認し、数値IDが確定した人だけを選んで、通常と同じ登録確認へ進みます。画像を読めない場合は名前・プロフィールIDの入力から同じ検索を使えます。中止・時間切れ・検索失敗では登録を進めません。

画像から全フォロワーを自動取得する機能ではありません。日本語・装飾名の認識率は画像と端末に依存し、利用者のiPhone／Android実機での精度確認は残ります。Spoonのパスワード・Cookie・トークンを登録する手順は追加していません。公式のフォロワー連携・ブックマークレットは未対応です。

## 一覧・更新の見方

管理者のユーザー一覧は、ログイン名と実際の「管理者／利用者」権限だけを常時表示します。展開すると表示タグ・プロフィール設定・パスワード状態・許可された操作が出ます。表示タグを「管理者」に変えても権限は変わりません。既存のkitomoya保護・自分の権限変更制限・CSRF・確認操作を維持します。

ファンの「いま聴いている」は温度付きの保存済み最新観測による目安です。正常な収集workerと完了した巡回が確認できる場合、巡回時間と待機時間に合わせて判定範囲を10〜30分に調整します。停止・失敗・部分取得・通信制限待機・古いheartbeat・情報不足では延長しません。そのDJの新しい取得で温度なし・不在になった人や、新しい枠取得の失敗も確認して優先度を下げます。「最近」は30分です。現在の聴取は保証しません。

画面の「表示確認」はDBを読んだ日時で、リスナーの実観測日時とは別です。一覧は30秒ごとに確認し、進行中の自動通信を中断しません。手動の対象・条件・ページ変更では古い通信を取り消し、結果の混入を防ぎます。各一覧の要求は60秒で時間切れとなり、前回の表示を維持して次回に再試行します。

「まめ／ゆん」の元の0表示は本人の数値ID・API診断が未取得で、実際の原因が確定したとは扱いません。今回の一般的な判定・表示改善と、この個別事例の原因究明は区別します。

スマホの出現先の名前欄が1文字幅になる問題は、名前・IDを上段、観測情報を下段に分けて修正しました。詳細ポップアップは見出しと本文のスクロールを分け、別ユーザーの詳細を開くと本文の先頭へ戻ります。PCの狭い詳細ペインにも対応します。

## 確認すること

- 自枠より後の他枠観測が一覧に出て、展開時に自枠の基準と区別できること。
- ファン未登録の一般利用者が、スマホから自分のプロフィールを確定し、自枠／月間候補を確認できること。
- 同名の人を数値IDで選び、部分追加と個別解除が他の登録・アカウントに影響しないこと。
- 画像補助で候補の編集・数値ID確認・キャンセルができること。読み取り失敗時は手入力へ戻れること。
- 320・360・390・414pxとPCで、長い名前・ID・温度0／欠損・部分取得・観測時間帯を読めること。
- ログイン、既存のパスワード、ファン、お気に入り、管理者権限が保持されていること。
- 本番更新後に公開用Webの起動とURLを確認し、保存済みの観測日時が進んでいるかを確認すること。
