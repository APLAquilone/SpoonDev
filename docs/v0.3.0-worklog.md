# v0.3.0 作業記録

対象: `/workspace/SpoonDev`、`dev/v0.3.0`。開発はMacの `~/SpoonDev-dev` と `http://localhost:8081`。この作業の配布先はDevです。開始時のmainはv0.2.2、`1b012c73217a6aa960ac463b38abaf4bdde9193c`。

## ユーザーの要件と完了内容

- 活動時間の認識を修正。自分の登録ファン・今月自枠で観測した人・正の月間温度メンバーを対象に、他のDJも含めたリスナー観測を集計。日付×時間帯のみに整理。
- ユーザー詳細の ↺ 再読み込み、「出現時間」の個人グラフ、最新の観測時間範囲。出現先のDJ名クリックで詳細へ移動。
- ファン初回設定をファン検索内へ移動。一般利用者の初回確認と紐付けロックを保持。ファンを聴取中の目安／最近の観測／登録したファンへ分類し、全件の分類・並べ替え後にページ分割。欠損温度・新しい取得での不在は優先度を下げる。
- 「ライブ観測」を「リスナー観測」に変更し、配信中のON AIRとは区別。
- 収集のタスク例外を分離し、DB障害時は取得スレッドを取り消してから復旧。監視プロセスが異常終了を5〜60秒で再試行。共有429待機・DBの排他制御を保持。
- Macのユーザーlaunchdサービスを導入・確認・解除する補助スクリプト。Web／Tunnelと別に収集し、フォルダごとにサービスを分離。読み込まれたサービスが停止中なら、そのサービスだけをkickstartで再開する。
- 管理者の右上に「お知らせ管理」を追加。日付・重要度・内容を作成／編集／削除／予約。実際の利用者ロールの画面に共通のお知らせを表示。表示タグと権限を混同せず、既存のログイン・お気に入り・ファン設定を保持。

## 性能と確認

通常の一覧から28日分の指数の再計算と、お気に入りごとの詳細取得を削除。詳細を展開すると同じ指数を取得する。個別DJの月間取得で毎回全DJのプロフィールを読み出す処理も削減。

一覧の観測範囲は直近30分に限定し、時間範囲の注記を付加。個人詳細の全履歴は維持。同じDBと固定時刻で、5,040観測・252,000memberships・対象50人のファン一覧は4.15秒→0.22秒、お気に入りは4.01秒→0.21秒。測定結果 `/tmp/v030-query-before.json`、`/tmp/v030-query-after.json`、再現 `/tmp/v030-fixed-benchmark.py`。

Python全268テスト成功、ログ `/tmp/spoon-v030-full-tests.log`。認証ブラウザ160項目が320／390／1365pxで成功、JSエラー・ページ横はみ出しなし。活動・ファンの90項目とお知らせ70項目の結果・画像は `/tmp/v030-ui-qa/`。新規wheelの内容を確認済み。

初回全体検証では旧v0.2.1の「一覧に常にinsightsがある」というテストが失敗した。詳細／ダッシュボードの同じ指標を検証しつつ、コンパクト一覧では遅延取得する新仕様に更新後、全268件を再実行して成功した。ほかの旧テストは新分類の優先度と収集監視の起動方法に合わせ、元の所有プロセス・HUP・待機期限の検証を保持した。

## 運用上の事実

Devの自動収集は既定OFF。Webは保存済みデータでも動作する。取得周期はリスナー300秒・ランキング3600秒だが、走査完了後の待機に取得時間・共有ペース制御が加わる。人数・連続滞在・現在の聴取・アプリ起動終了時刻を断定しない。時間セルに対象者の観測がなければ未知として扱い、他枠の完全取得を本人の不在の証拠にしない。

公開APIの少量照合でディレクトリ・月間温度・Spoon指標の形式を確認。リスナー32件中2件は温度nullだったため、欠損温度の優先度ダウンは実際の応答を踏まえる。

このクラウドから利用者のMacに接続していない。Macの現在の収集状態、launchdの実常駐、公開URLの切り替えは未実行。GitHubのDev配布とMac本番デプロイを混同しない。次は利用者が [Dev更新手順](v0.3.0-dev.md) で画面確認する。
