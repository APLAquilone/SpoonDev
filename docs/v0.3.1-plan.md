# v0.3.1 修正予定

## スマホのユーザー詳細・出現先一覧のレイアウト修正

- [ ] **優先度: 高。** ユーザー提供の `6948.jpg` で確認した表示崩れを修正する。

### 症状

ユーザー詳細の出現先一覧で、名前・プロフィールID・数値IDの列が極端に細くなり、ほぼ1文字ずつ縦に折り返されている。観測日時・温度・「温度履歴」ボタンとの横並びで、行の高さが大きくなり、一覧を読みにくい。

### 修正方針

- スマホでは名前・IDと観測情報を段に分け、名前欄の幅を確保する。
- 観測回数・観測時間帯・温度・履歴ボタンを、読みやすさと一覧性を保つ配置にする。
- 長い表示名・プロフィールID・観測期間でも、一文字幅まで名前欄が縮まないようにする。
- 詳細ポップアップをスクロールした際、固定ヘッダーと説明文が重なって読みにくくならないかも確認する。

調査対象は `spoondev/static/index.html` の `renderDetail()`、`.relation`、`.relation .person`、`.listener-observed-range` と、`spoondev/static/theme.css` の文字サイズ・モーダルの設定。横並び要素の幅配分が原因候補だが、ブラウザで再現してから確定する。

### 完了条件

- 画面幅320・360・390・414pxで、名前とIDが読める幅を保ち、横にはみ出さない。
- 長い日本語名・英数字のプロフィールID・9桁の数値ID・長い観測期間でも、不自然に高い行にならない。
- 温度履歴の有無、月間温度／リスナー観測の切り替えで崩れない。
- 温度履歴・プロフィール・閉じるボタンをスマホで操作できる。
- PC表示の一覧性も確認する。

## ファン検索の聴取分類と一覧の更新表示

- [ ] ファン検索で実際に聴取中の人がいても「いま聴いている」が0になる事例を照合する。

2026-10-11の報告: お気に入りは更新される一方、ファン検索の聴取中欄が0。対象例は「まめ」が「ゆん」の枠を聴いている状態。表示名は一意ではないため、本人のファン一覧のAPI応答から数値ID・観測日時・温度・出現先を確認する。Macの収集は同じPIDで継続し、00:51:01時点まで保存、直近30分836観測を確認済み。

確認できた仕様と改善対象:

- お気に入りの上段は直近30分のリスナー観測。ファン検索の聴取中欄は直近10分・温度あり・そのDJの最新保存記録を必要とする。同一IDの判定処理は共通だが、画面の区分が異なる。
- 全枠の巡回時間と、その後5分の待機に対して、固定10分の判定期限が短くなる場合がある。最新のDJ取得で確認できている人が、次の巡回前に期限だけで降格する問題を検証し、実際の取得間隔に合う判定と説明を設計する。
- 判定期限を変更する場合は、正常な巡回の実行時間と待機時間を使った調整を検討する。停止・失敗・部分取得・通信制限待機・記録不足では古い状態を延命せず、対象枠の新しい取得失敗も照合する。本人の記録を確認するまで固定10分の分類は変更しない。
- 最新取得で温度なし・対象者不在の場合は、過去の温度だけで聴取中に昇格させない。部分取得・未取得・停止中は不明として扱い、実際の視聴を保証する表示にしない。
- 名前検索・活動フィルター・ファン登録の有無も照合する。登録ファンの範囲とアカウント間の分離を保持する。
- 一覧の「データを確認した日時」と「その人を観測した日時」を区別できる表示にする。ファン検索は画面復帰時にも再確認する。
- [x] 自動更新が進行中の通信を中断し続けないようにする。検索条件・ページ・対象者の手動変更では、古い結果の混入を防ぐため通信の中断を維持する。各API要求に60秒上限を設け、失敗時は前回データを保ち、次回確認で再試行する。ファン検索の画面復帰時の再確認と表示確認日時も追加した。
