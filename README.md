# SpoonDev

Spoon 日本版の公開配信・リスナー一覧を取得し、配信者とリスナーの関係と温度 (`favorite_temperature`) を時刻付きで SQLite に蓄積します。Python 3.12 以降と標準ライブラリ、バックグラウンド起動には Linux の `flock` を使います。

## 保存する情報

- 数値のアカウントIDを主キーにします。同名の別ユーザーを区別できます。
- プロフィールに表示されるID (`tag`) と表示名 (`nickname`) は別に履歴として保存します。ハンドルが将来変更されても数値IDで追跡します。
- 配信ID、配信者ID、リスナーID、UTC観測日時、取得できた温度を保存します。温度は配信者とリスナーの関係ごとの観測値です。温度の計算方法は断定しません。
- 全ページ取得と部分取得を区別します。取得失敗を「リスナー0人」や退出の証拠にしません。

取得できるのは API が公開するリスナーです。匿名・非表示リスナーの身元は分かりません。ページを取得する間にも入退室が起きるため、完全に同時刻の一覧ではありません。集計の回数は観測回数であり、実際の視聴時間ではありません。

## 開発・検証

既存の `/workspace/SpoonDev` を使います。クラウドタスクは独立した環境なので worktree を追加する必要はありません。依存パッケージの導入やログイン、シークレットは不要です。

```sh
cd /workspace/SpoonDev
python -m unittest discover -s tests -v
python -m spoondev init-db
python -m spoondev collect-spoon --max-rooms 3 --once
```

Spoon の Web クライアントが使う `https://jp-api.spooncast.net/lives/` と `/lives/{id}/listeners/` を実応答で確認しています。`next` の同一ホスト・同一パスのURLを巡回し、全ページのリスナーを取得します。配信終了やエラー時は部分観測か失敗として扱います。音声、メール、認証情報、APIの生レスポンスや room_token は保存しません。

## 定期収集

```sh
python -m spoondev collect-spoon --max-rooms 0 --interval 300 --concurrency 4
```

`--max-rooms 0` は配信一覧に載る全配信が対象です。既定値は10配信なので、全配信には明示的に0を指定します。ページ数の安全上限は各一覧100ページです。上限に達するとエラーを報告するため、全件取得を断言しません。配信ごとに並列取得し、同一ホストへのリクエスト開始には間隔を設けます。最低周期は30秒ですが、通常は5分以上にします。取得ラウンド完了後に指定時間待つため、厳密な時計上の5分周期ではありません。

バックグラウンド起動は以下です。ファイルロックにより同じDBのコレクターが二重起動するのを防ぎます。

```sh
bash scripts/start-collector.sh
```

ログは `data/collector.log`、DBは `data/spoondev.sqlite3` です。直近起動要求のPIDは `data/collector.last-start.pid` にあります。二重起動の要求は終了するため、PIDの存在だけで稼働判定せず、ログとDBに新しい観測があることを確認します。終了には稼働中の `python -m spoondev ... collect-spoon` プロセスにSIGINTかSIGTERMを送ります。クラウド環境の停止・再作成・Publishでプロセスは維持されません。保存した起動手順に従って再起動してください。この開発環境が常時稼働サーバーになる保証はありません。

## 集計と温度履歴

```sh
python -m spoondev report broadcaster NUMERIC_BROADCASTER_ID
python -m spoondev report listener NUMERIC_LISTENER_ID
python -m spoondev history NUMERIC_BROADCASTER_ID NUMERIC_LISTENER_ID
```

`report` は観測回数、初回/最終観測、プロフィールID、最後に取得できた温度を返します。欠測は0と扱いません。温度の取得日時は `history` で確認できます。履歴には未取得の温度も null として現れます。

任意のDBには `python -m spoondev --db /path/to/db.sqlite3 ...` を使います。`examples/snapshot.json` は架空のデータで、本番DBにインポートしないでください。JSONインポートと、検証済みJSONアダプター向けの汎用 `collect --url ...` も利用できます。同じ観測の再インポートは新しい観測として記録されます。

## 検索Webサイト

```sh
cd /workspace/SpoonDev
python -m spoondev serve --port 8080
```

表示名・プロフィールID・数値IDで検索し、「出現先」を表示します。「訪れたリスナー」のタブは削除しました。検索語を入力すると既定ではSpoonの公開ユーザー検索に問い合わせるため、ライブでまだ観測していないアカウントも検索できます。検索語が空の場合と「Spoon全体から検索」を外した場合は保存済みユーザーを検索します。同名のユーザーには数値IDを併記し、日時は日本時間、未取得の温度は「—」です。検索結果は50件ずつ切り替えられます。公開検索対象外のユーザーまで網羅するものではありません。検索APIの選出結果とページ上限にも依存します。

スマホ幅では、検索結果のユーザーをタップすると詳細ポップアップがすぐ開きます。「閉じる」で元の検索結果に戻れます。ポップアップ内で出現先のユーザーや温度履歴も開けます。PC幅の検索では右側に詳細を表示し、お気に入り・ファン一覧では詳細ポップアップを使います。

ユーザー詳細の「お気に入りに登録」で数値 ID を保存し、検索欄の「お気に入り」から一覧を開けます。一覧・詳細のどちらからも解除できます。保存先はブラウザのローカルストレージです。PCとスマホでは共有されず、同じブラウザでもアクセス先のIPやポートが変わると別の一覧になります。ブラウザのサイトデータを削除するとお気に入りも消えます。
お気に入り一覧は「最近配信に入っていたユーザー」と「お気に入りのユーザー」に分かれます。直近30分以内にリスナーとしてライブ観測されたユーザーを上段に表示し、30秒ごとに保存済みライブ観測を確認します。月間温度やプロフィールの更新日時では振り分けません。観測された日時を示すもので、現在も視聴中とは限りません。



「出現先」は「月間温度」と「ライブ観測」を分けています。「月間温度」は配信者側の月間リスナーランキングを逆引きした関係で、現在視聴中という意味ではありません。「ライブ観測」は実際の取得時点に見えた参加関係で、過去の観測も含みます。「ライブ観測」の温度履歴はグラフと一覧で確認できます。

既定ではこの環境のループバックインターフェースの8080番ポートで起動します。クラウドのオンボーディング画面はローカルWebプレビューを提供しないため公開URLはありません。手元でリポジトリとDBを実行すると、同じマシンのブラウザから使用できます。家庭内Wi-Fiからの接続には `python -m spoondev serve --host 0.0.0.0 --port 8080` を使います。外部公開・認証・HTTPSは含めていません。

バックグラウンド起動には `bash scripts/start-web.sh` を使います。ログは `data/web.log`、起動要求のPIDは `data/web.last-start.pid` です。ファイルロックで重複起動を防ぎます。表示用の検索・集計接続は読み取り専用ですが、Spoonの公開検索で取得したプロフィールはDBにキャッシュします。収集プロセスを止めずに検索できます。利用者が履歴を書き換える機能はありません。環境再作成時には収集・月間ランキング収集・Webサイトを再起動します。

## 月間ランキングからの出現先と検索対象の拡張

```sh
python -m spoondev collect-monthly --max-djs 0 --once
python -m spoondev collect-monthly --max-djs 0 --interval 3600 --concurrency 4
```

1つ目は1回、2つ目は各収集回の終了から1時間待って繰り返します。Webサイトとは別のターミナルで実行します。`--max-djs 0` はライブ収集で既知になった全配信者が対象です。既定値は100配信者です。先にライブ収集を実行し、配信者を発見してください。最近活動した配信者を優先し、4並列で取得します。同一ホストへのリクエスト開始間隔は0.25秒以上です。100配信者ごとに進捗を出し、終了した配信者ごとに逐次保存するため、全件終了を待たず出現先が検索画面に反映されます。Linuxでは `bash scripts/start-monthly.sh` でバックグラウンド起動できます（Macでは上のPythonコマンドを使用）。

取得元は公式Webクライアントの `https://jp-gw.spooncast.net/favorite-temperatures/djs/{id}/rankings?rankType=MONTHLY` です。指定されたプロフィール `/jp/channel/317015673/tab/home` の実ランキング応答でも確認しています。その画面の「全体」は `ALL_TIME`、「月間」は `MONTHLY` なので同一視しません。リスナー一覧を配信者→リスナーの方向で取得し、保存済みランキングをリスナー→配信者へ逆引きします。月間ランキングは年月を指定する呼び出しではないので、過去月を後から取得できるとは想定せず、取得したデータを月・日時付きで履歴保存します。

公開検索で見つけた人と、月間ランキングで見つけた人を同じ数値IDで検索対象に追加します。ただしランキングの対象は既知の配信者であり、Spoon全配信者・全アカウントの完全な列挙ではありません。まだ未知の配信者への出現先は拾えません。月間ランキングは既定でページ数の上限を設けず、最後のページまで取得します。必要な場合だけ `--max-pages 100` などで任意の上限を指定できます。`--max-pages 0` は上限なしです。画面では取得済みの月間ランキング数と取得元を表示します。取得エラーは「出現先なし」の証拠にしません。

月が変わったら前月の温度を当月データとして表示しません。配信者ごとに最新の取得結果を使い、成功した空ランキングは以前の関係を更新します。全失敗では以前の保存データを維持します。APIの429応答は後続取得を止め、指定された待機時間に従います。

## 接続と運用上の制約

必要な接続先は `www.spooncast.net`、`jp-api.spooncast.net`、公開検索・月間ランキング用の `jp-gw.spooncast.net` です。公式Webクライアントが参照する利用規約・プライバシーのホストは `spoonvip.oopy.io` と `spoon-privacy.oopy.io` で、接続許可を設定ドラフトに追加しています。現在、その規約ホストへの接続はプロキシ403で遮断され、規約本文は未確認です。公開APIへのアクセス成功は大規模・長期収集の利用許可を意味しません。長期運用前に利用条件を確認してください。

DBとログはGitから除外しています。個人単位の行動履歴を含むため、アクセス範囲と必要な保存期間を決めて運用してください。データや分析結果は自動公開しません。


### ご自身のフォロワー（fan）の出現先

Spoonの公式ブラウザではフォロワー一覧は本人のみ表示でき、ログインなしの取得は403で拒否されます。月間温度ランキングのユーザーとは別物です。本機能は本人のブラウザから保存した一覧を取り込み、既存の月間ランキング・ライブ観測と数値IDで照合します。Spoonのパスワード・トークンを入力・保存する必要はありません。

1. SpoonDevで自分のアカウントを検索し、詳細の「ファンを登録・確認」を開きます。
2. PCのブラウザ版Spoonにログインして、自分の `https://www.spooncast.net/jp/channel/数値ID/tab/home` を開きます。
3. SpoonDevの取り込み欄にある「一覧保存スクリプトをコピー」を押し、コピーした内容をSpoonページの開発者ツール（Macでは Option+Command+I）のConsoleに貼り付けて実行します。本人IDを照合し、フォロワー全ページを取得して `spoon-fans-数値ID.json` を保存します。429などで失敗した場合は全件ファイルを作らず停止します。Spoon公式の現在確認済みのJSビルドを使うため、仕様変更時は更新が必要です。認証済みの実アカウントでの取得は、このクラウドでは検証できません。
4. SpoonDevへ戻り、保存したJSONを選択します。「自分のアカウント」と「全件一覧として置き換える」を確認して「一覧を登録」を押します。全件置き換えでは以前登録したうち一覧にいないファンが解除されます。部分一覧・手入力は置き換えを選ばず追加してください。数値IDを改行・カンマ区切りで入力する方法も使えます。
5. 「ファン登録」タブに配信者が保存されます。PC・スマホから同じサーバーにアクセスすれば同じ登録一覧を使えます。

ファンの出現先には、今月の月間温度ランキングと直近30分のリスナーとしてのライブ観測を表示します。各ユーザー・取得元ごとに最大3件を表示し、名前を押すと詳細の全記録を確認できます。50人ずつページを切り替えられ、開いた一覧は30秒ごとにDBを確認します。新しい出現先は既存の収集処理から反映されますが、フォロー・解除の変更は新しい一覧の取り込みが必要です。把握していない配信者、未観測のファンには出現先が出ません。「見つからない」は活動がない証拠ではありません。

ファン登録・一覧はSQLiteに保存され、Spoonのログイン情報は保存されません。お気に入りのブラウザ保存とは異なります。取り込みファイルは8MBまでです。APIは `GET /api/fan-owners`、`GET /api/fans?owner_id=数値ID&offset=0`、`POST /api/fans/import`（同じサイトからJSON、owner/followers/complete）です。サイト全体は公開運用用の認証を備えていません。自宅LAN向けの既存の起動方法を使ってください。

一覧保存スクリプトはコピー用の読み取り専用コード欄から取得します。ブラウザの自動翻訳で `try` が「試す」に変わったコードは実行できません。コピー機能はHTTPのLAN接続でも利用できます。コピーできないブラウザでは、表示されたコード欄を全選択してコピーしてください。

ファン一覧はお気に入りと同じユーザー行の表示です。「最近配信に入っていたユーザー」と「登録したファン」に分け、最近の観測がある人を全登録ファンの中から先に並べます。名前・プロフィールID・数値ID・最終ライブ観測日時を表示し、名前を押すと詳細の出現先を開きます。スマホでは詳細を閉じるとファン一覧へ戻ります。星ボタンでお気に入り登録・解除もできます。

お気に入り・ファン一覧の各行には、最近のライブ観測と月間温度の出現先を各3件まで表示します。出現先の名前から相手の詳細へ移動できます。お気に入りの出現先は一覧表示中に最大4件並列で読み込み、30秒ごとに再確認します。全記録はユーザーの詳細から確認できます。

「ファン登録」タブでは、登録済み配信者のファン一覧を画面内に直接表示します。配信者が1人ならタブを開くだけで一覧が表示され、複数なら選択欄で切り替えられます。前回選択した配信者をブラウザに記憶します。ファンの名前から詳細ポップアップを開き、閉じると元の一覧・ページに戻れます。ファン一覧自体はポップアップを使いません。

名前の左の赤い「ON AIR」は、直近のSpoon公開配信一覧に本人が配信者として載っていることを示します。検索結果・お気に入り・ファン・ユーザー詳細で30秒ごとに確認し、一覧をサーバー側で30秒キャッシュします。過去のライブ観測やリスナー参加だけでは点灯しません。取得に失敗した場合は古いバッジを消します。配信終了の反映に最大約1分かかる場合があります。バッジがないことは非配信の証明ではなく、非公開・一覧外の配信は判定対象外です。

画面は深いグリーンをベースにミント色をアクセントとして使うデザインです。タイトルは意図した2行構成、集計値は個別カード、ユーザーは出現先付きのカードで表示します。PCではお気に入り・ファン一覧を全幅の2列で表示し、詳細はポップアップで開きます。スマホでは1列に切り替わります。外部フォント・外部UIライブラリは不要です。ファン一覧の取り込みに成功すると入力欄を閉じ、登録結果と一覧を表示します。

詳細画面のユーザー名（↗）を押すと、その数値IDのSpoonプロフィールを開きます。PCでは別タブ、スマホではアプリを優先します。

スマホの名前リンクはAndroidで公式スキーム `spooncast://deeplink/user?user_id=ID&country=jp` と公式パッケージ `co.spoonme` のIntent、iPhone/iPadで公式OneLink `https://spoon.onelink.me/Uuzo` を使用します。未インストール時のブラウザURLを指定し、直接「ブラウザで開く」リンクも用意しています。インストール状態をWebから判別しているわけではなく、起動可否はOS・ブラウザ・Spoonアプリの設定に依存します。実機でのアプリ受け渡しはクラウドでは検証できません。

### Macから無料の一時URLで公開・ログイン

Python 3.12の `spoondev` 環境を使います。既存の `serve` のターミナルだけ Ctrl+C で停止し、収集処理は動かしたままで構いません。

```bash
conda activate spoondev
cd ~/SpoonDev
git pull --ff-only
python -m pip install -e .
brew install cloudflared
python -m spoondev create-user kitomoya --claim-local-data
bash scripts/start-public-mac.sh
```

パスワードはMacのターミナルで2回入力します（12文字以上・入力中は表示されません）。表示された `https://…trycloudflare.com` をスマホやPCで開き、作成したユーザー名とパスワードでログインしてください。ルーターのポート開放は不要です。Macとターミナルを起動したまま使います。スリープ防止はスクリプトに含まれますが、Macの蓋は閉じないでください。URLは起動ごとに変わる試験公開用です。Cloudflare Quick Tunnelの可用性や接続数にはサービス側の制約があります。

追加アカウントは `python -m spoondev create-user alice`。パスワード変更は `python -m spoondev create-user kitomoya --reset`（既存のログインをすべて解除）。一般公開の新規登録はありません。

ログイン版ではお気に入りとファン登録を利用者別のDBに保存します。観測・公開プロフィールデータは共通です。`--claim-local-data` は既存のファン登録を指定アカウントだけにコピーする移行オプションです。ブラウザに保存していたお気に入りは自動移行されないのでログイン後に再登録してください。データは `data/accounts.sqlite3` と `data/account-data/` に保存され、Gitには入りません。これらも観測DBと合わせてバックアップしてください。

外部公開スクリプトは常に認証を有効にして127.0.0.1だけで待ち受けます。通常の `serve` は従来どおりログインなしのローカル利用用です。公開時のCookieはSecure/HttpOnly、変更操作はOriginとCSRFトークンで検証します。これはMacから少人数で試す構成であり、決済・メール・アカウント復旧・常時稼働のSaaS基盤は含みません。

ログイン版の「ファン一覧」とお気に入りは各アカウントで独立して設定できます。同じアカウントならPC・スマホで共有します。画面上部の全体集計（ユーザー数・ライブ観測数・月間取得配信者数・最終観測）は `kitomoya` のみ閲覧でき、集計APIも他アカウントには403を返します。個々のユーザーの出現先や温度の閲覧は引き続き利用できます。追加利用者には `--claim-local-data` を付けずにアカウントを作成してください。

「ファン一覧」の「ファン一覧の設定を解除」は確認後に、ログイン中の利用者・選択中の配信者の紐付けと登録ファンを削除し、設定を初期化します。ファン0人でも解除できます。お気に入り、観測・温度の記録、他アカウントのファン一覧は残ります。取り消しはできませんが一覧を再取り込みできます。

既存ローカル登録の移行 `--claim-local-data` は `kitomoya` 専用です。新規ログインユーザーには配信者を自動設定しません。すでに誤って引き継いだ登録がある場合は、そのログインで「ファン一覧の設定を解除」を押すと紐付けを解除できます。

### 開発用と公開用を分ける（Mac）

`~/SpoonDev` を公開用、`~/SpoonDev-dev` を開発用にします。公開側の収集・ログインDBはそのまま保持します。初回は公開用フォルダから実行します。

```bash
cd ~/SpoonDev
```

### 再起動しても変わらない公開URL

Quick Tunnelの `trycloudflare.com` URLは固定できません。固定URLはCloudflareで管理する独自ドメインと、無料の名前付きTunnelを使用します。Tunnel利用料は無料ですが、ドメインを持っていない場合は取得・更新料金が別途必要です。CloudflareアカウントへのログインとDNS設定は本人のブラウザで行います。

ドメインをCloudflareで管理したら、公開用Macで以下を実行します（`spoon.example.com` は自分のドメインに置き換える）。

```bash
cloudflared tunnel login
cloudflared tunnel create spoondev
cloudflared tunnel route dns spoondev spoon.example.com
```

作成時に表示されるTunnel UUID・認証JSONのパスを使い、`~/SpoonDev/data/public-tunnel.json` を次の形式で保存します。実際の認証JSONやトークンはGitやチャットに貼らないでください。

```json
{
  "url": "https://spoon.example.com",
  "tunnel_id": "作成時のTunnel UUID",
  "credentials_file": "/Users/自分のMacユーザー名/.cloudflared/Tunnel UUID.json"
}
```

`bash scripts/start-public-mac.sh` はこの設定があれば固定URLのTunnelを使い、なければ従来の一時URLを使います。設定は公開用だけに置きます。再起動・リリースでURLは変わりません。Macが停止するとアクセスできなくなる点は同じです。このLinuxクラウドではMac・本人のCloudflareアカウントによる固定URLの実接続は未検証です。


### Dev: 初回パスワード変更・管理コンソール・ナビゲーション

この更新は `dev/minor-upgrade` ブランチで確認します。公開用mainへは自動反映しません。開発用を停止して、`~/SpoonDev-dev` から次のコマンドで取得してください（未コミット変更がある場合は先に保存します）。

```bash
cd ~/SpoonDev-dev
git fetch https://github.com/APLAquilone/SpoonDev.git dev/minor-upgrade
git switch -c dev/minor-upgrade FETCH_HEAD
bash scripts/start-dev-mac.sh
```

アカウントDBは起動時に追加カラムを移行します。既存アカウントのラベルは「保守」、`kitomoya` の権限は管理者、その他は利用者です。既存ユーザーも更新後の最初のアクセスでパスワード変更が必要です。一度変更すると次回以降は不要です。変更には現在のパスワードと12文字以上の別パスワードを指定し、すべての既存セッションを解除して再ログインします。管理画面も変更完了まで使えません。

左ナビゲーションから検索・お気に入り・ファン一覧・パスワード変更へ移動できます。管理者だけに「ユーザー管理」を表示し、一覧・ユーザーID/初期パスワード/ラベルで作成・ラベル変更・利用者削除ができます。初期パスワードは管理者が指定して本人へ渡します。一覧ではパスワード・ハッシュを返しません。作成された利用者には初回パスワード変更を強制します。管理者自身は削除できません。利用者削除でログインと全セッションを無効化し、復旧用の私有DBファイルは管理者のバックアップ領域に保持します。同じID名を再作成しても新しい内部IDと空の保存領域になり、旧データを引き継ぎません。

ラベルは「保守」「プラン1」「プラン2」「プラン3」の候補や任意の1〜64文字で変更可能です。ラベルは権限と独立した管理情報で、現時点では決済・利用制限には連動しません。CLIでも `create-user <ID> --label 保守` で設定できます。管理者権限をラベル変更で付与することはできません。

ファン一覧の並び替えは、最近30分の観測を優先／最終ライブ観測が新しい順／古い順／名前順／名前の逆順／数値ID順です。全登録ファンを並べてから50人ずつページ分割します。未観測のユーザーは観測日時の並び替えで末尾に置きます。名前順は保存済みの表示名の文字順（ASCII英字の大小は区別しない）で、読み仮名順ではありません。観測日時は取得した記録に基づき、実際の全活動を示しません。


Dev管理者権限: 「管理者」というラベルだけでは権限は変わりません。MacのDevフォルダから `python -m spoondev set-role spdev001 admin` で管理コンソール権限を付与できます（解除は `user`）。管理画面にも別の利用者の「管理者権限を付与／解除」を追加しました。権限変更は対象の全セッションを無効化するので再ログインが必要です。追加した管理者権限はサーバー再起動やユーザー作成でも維持します。kitomoyaの権限解除と管理画面からの自分自身の権限変更はできません。全体集計の閲覧は引き続きkitomoya専用です。

Devの一覧で「最近のライブ観測」は直近30分に限定し、詳細のライブ観測は過去の記録を含みます。月間温度は別途保存したMONTHLYランキングに基づき、ライブ温度から補完しません。詳細の月間取得範囲は「取得済み配信者のみ」と表示し、取得範囲の制限とランキングページの部分取得を区別します。Mac上の実データでの欠損原因を調べるには、当該配信者の現在月のランキング収集状況を確認する必要があります。

Devナビゲーションの「データの取得範囲」画面に、ライブ・月間・ON AIR・検索・ファン登録・お気に入りの対象と更新頻度を掲載しました。標準収集は1巡完了後にライブ5分／月間1時間待機し、画面の30秒更新とは別です。設定引数、ページ上限、エラー、Mac停止、Spoon側更新による遅れも明記しています。公開環境で起きた月間欠損の診断には公開環境のDB・収集ログを使い、Devコピーとの差を原因と断定しないでください。
